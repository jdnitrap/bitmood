cmix-bit — mechanical breakdown

What each part does, in order, for one bit. No extra train or fine-tune stage.

0 What the machine is

A file is bytes. Each byte is 8 bits, MSB first. The model asks eight times: is the next bit 1?

byte 0x48 'H' = 0 1 0 0 1 0 0 0

After bit 7 the byte is committed to hist, hashes, and the match window.

1 One-bit loop

  1. Build context from finished bytes + bits already decided in this byte.
  2. Each specialist returns P(bit=1) as 1..4094.
  3. Mixer turns those six numbers into one p.
  4. Compress encodes the real bit with p. Decompress recovers the bit from p. Demo prints p. Generate samples p.
  5. Everyone updates from the real bit.
  6. Shift the bit into partial. On bit 7, commit the byte.
for each byte: for k in 0..7: p = mix(specialists) use p update(bit)

3 Specialists

2048 = no idea. They do not talk to each other.

A recent pattern

1M-slot n0/n1 table hashed from last bytes + bit_index + partial.

B long match

Longest suffix in the window; take the bit that followed it.

C byte-shape flags

MDBE flags: alpha/digit/upper/punct/space/utf8. Hardcoded prior.

D0 D1 D2 order-N

Three more n0/n1 tables on three running hashes.

4 Stretch / squash

stretch(p)=ln(p/(1-p)) squash(z)=1/(1+e^{-z})

Add in logit space, then fold back to a probability stored as 1..4094.

5 Mixer

z = sum (w_i * stretch(p_i)) / 128 p = squash(z) err = (bit?4095:0) - p nudge each w_i

This is the training. It runs on every bit. Weights stay in 1..1024.

6 Arithmetic coder

  1. Split [x1,x2] at p/4096.
  2. Keep the upper piece for bit 1, lower for bit 0.
  3. When top bytes of x1 and x2 match, emit or consume that byte.
header: CMXB + 8-byte length then payload + 4-byte flush

7 Update

  1. Mixer uses err.
  2. A and D increment n0 or n1; halve when the pair gets large.
  3. On bit_index==8: push byte into B and hist; refresh hashes.
